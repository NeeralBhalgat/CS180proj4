Part A.2

Recovering homographies

I selected 29 point correspondences between the two poster photographs using the CS180 correspondence tool. The figure overlays the photos with colored lines connecting matching scene features.

A homography maps a point (x₁, y₁) in Image 1 to its match (x₂, y₂) in Image 2:

[x₂, y₂, 1]ᵀ ∼ H [x₁, y₁, 1]ᵀ H = [[h₁, h₂, h₃], [h₄, h₅, h₆], [h₇, h₈, 1]]

Fixing the bottom-right entry to 1 leaves eight unknowns. Each correspondence contributes two rows to the linear system A h = b:

For one correspondence (x₁, y₁) → (x₂, y₂): Aᵢ = [[ x₁ y₁ 1 0 0 0 -x₁x₂ -y₁x₂ ], [ 0 0 0 x₁ y₁ 1 -x₁y₂ -y₁y₂ ]] bᵢ = [x₂, y₂]ᵀ h = [h₁, h₂, h₃, h₄, h₅, h₆, h₇, h₈]ᵀ Stack all Aᵢ and bᵢ rows, then solve A h ≈ b by least squares.

Using all 29 correspondences, computing H gives this homography from Image 1 to Image 2:

Part A.3

Warping and rectification

Rectification 1 · Star Wars poster

The Star Wars poster has four obvious corners. I selected these corners in top-left, top-right, bottom-right, and bottom-left order and mapped them to an 800 by 1200 pixel rectangle. I then transformed the image corners to determine the output canvas area. From there, I iterated through the pixels in this canvas and multiplied each pixel's homogeneous coordinates by the inverse homography to find its source location. For nearest-neighbor sampling, I rounded the source coordinates to select the nearest pixel. I also used bilinear warping, where I kept the decimal source coordinates and calculated a weighted average of the four surrounding pixels based on their horizontal and vertical distances.

Rectification 2 · Wave print

I selected the outer corners of the hanging poster and mapped them to an 800 by 1280 pixel rectangle.

I treat integer coordinates as pixel centers, with (0, 0) at the center of the top-left pixel. The canvas bounds come from the transformed image corners. Output locations that map outside the source image remain black. The target rectangles specify the poster regions; the complete output canvases also include the warped surroundings.

Speed and quality trade-offs

Both methods gave me the same rectified geometry, and at this size, the results look almost identical. Nearest-neighbor sampling takes the color of a single source pixel, which keeps the original pixel values but can make edges look jagged. Bilinear sampling blends nearby pixels, making text and edges look smoother but sometimes slightly blurry. Neither method can fix the curves already present in the physical paper.

In my loop-based implementation, bilinear sampling took about twice as long as nearest neighbor. This makes sense because bilinear interpolation combines four source pixel colors for each output pixel, while nearest neighbor only needs one. The exact timings also depend on the image size and the computer running the code.

Both warpImageNearestNeighbor and warpImageBilinear are implemented in proj4a.py. Running the file generates all four rectifications and prints the time taken by each warp.

Part A.4

Blending images into mosaics

Simply placing one warped image on top of another can leave a visible seam, especially when the lighting or alignment is slightly different. To make the transition smoother, I use feather blending. Each image gets a weight of 1 at its center, which gradually decreases to 0 toward its edges. This lets the images blend together instead of creating a sharp boundary.

I keep Image 1 fixed and warp Image 2 into its coordinate system. I calculate the canvas size using the corners of both images and use bilinear interpolation when warping. In areas where the images overlap, I combine their colors using a weighted average:

mosaic = (w₁ × color₁ + w₂ × color₂) / (w₁ + w₂)

If only one image covers a pixel, it keeps that image's color. Pixels outside both images stay black. I calculate the feather weights in each image's original coordinates and use a very small positive weight at valid edge pixels.

I also reuse warpImageBilinear to get the warped image, feather weights, and canvas position. Then makeMosaic combines everything onto one canvas. Feather blending helps hide seams, but it doesn't fix alignment errors, parallax, or perspective stretching.

Part B.1

Harris Corner Detection and ANMS

I run the instructor's single-scale Harris detector on grayscale versions of the six Part A photos, without sub-pixel refinement. The detector uses the response 2 det(M) / (trace(M) + epsilon), Gaussian scale sigma = 1, and excludes a 20-pixel border. I additionally keep only positive corner responses above 1% of the maximum response in each image.

Harris can produce many nearby candidates in textured regions such as poster lettering. To choose points that cover more of the image, I apply adaptive non-maximal suppression (ANMS) with c = 0.9 and retain 500 candidates per image.

r_i = min_j ||p_i - p_j||, where score_i < 0.9 * score_j Keep the 500 candidates with the largest r_i.

For each candidate, ANMS measures the distance to the nearest sufficiently stronger candidate. A candidate near a stronger one receives a small radius, while one farther away receives a larger radius. Candidates with no sufficiently stronger neighbor receive an infinite radius. Keeping the largest radii encourages spatial coverage; ties are broken by corner score and then candidate index.

Each comparison shows all thresholded Harris candidates on the left, the 500 strongest scores in the middle, and 500 ANMS-selected candidates on the right. The middle and right panels use the same number of points so the effect of the selection rule can be compared directly. Click a figure to inspect it at full resolution.

Part B.2

Feature Descriptor Extraction

Each ANMS-selected corner is described by an axis-aligned 8 by 8 grid of grayscale intensities sampled from a 40 by 40 pixel region. This follows the five-pixel sample spacing in Section 4 and Figure 4 of Brown et al.'s MOPS paper, with the assignment's simplifications: no orientation alignment, no multiscale detection, and no Haar wavelet transform.

For each corner, I extract a 40 by 40 grayscale patch and smooth it with a Gaussian filter (sigma = 2 pixels) to reduce aliasing. I sample rows and columns 2, 7, 12, 17, 22, 27, 32, and 37 of the blurred patch, producing an 8 by 8 descriptor with five-pixel spacing. This simple integer grid uses patch smoothing rather than the paper's higher-pyramid-level sampling.

After sampling, each descriptor has its own mean subtracted and is divided by its own standard deviation. Nonconstant descriptors therefore have mean zero and standard deviation one, reducing sensitivity to additive brightness changes and positive contrast scaling. A small denominator floor prevents division by zero for constant patches.

descriptor = (sampled_patch - mean(sampled_patch)) / max(std(sampled_patch), 1e-8) Descriptor shape: 8 x 8 = 64 intensity values per corner

Each figure shows eight source neighborhoods above their corresponding normalized descriptors. Each descriptor is displayed with its own grayscale range and enlarged without interpolation so the individual samples remain visible.

Part B.3

Feature Matching

For each descriptor in the first image, I compare its 64 normalized intensity values with every descriptor in the second image. The matching error is the sum of squared differences (SSD): smaller error means more similar patches. I sort these errors to identify the best and second-best candidates.

I use the two-neighbor ratio test described in Section 5.1 and Figure 6b of the MOPS paper. A match is kept only when its best SSD is less than 0.8 times its second-best SSD. The threshold applies to squared distances; it is an implementation choice rather than a claim that the paper prescribes 0.8. Testing the inequality without division also rejects the ambiguous case where both errors are zero.

SSD(i, j) = sum((descriptor_1[i] - descriptor_2[j]) ** 2) Accept best match when SSD_best < 0.8 * SSD_second_best

This test favors a distinctive best match over two similarly good alternatives. Matching runs from image 1 to image 2 without a mutual-match or one-to-one constraint, so multiple source features may choose the same destination. No wavelet indexing or multi-image outlier model is used. These are candidate matches before RANSAC; incorrect matches can remain and will be addressed in B.4.

Part B.4

RANSAC for Robust Homography

Descriptor matching produces candidate correspondences, including incorrect ones. I implement four-point RANSAC from scratch: sample four match pairs, estimate a homography using my Part A solver, and test how many of all the candidate pairs agree with that transformation. No library RANSAC or homography estimator is used.

I run 2,000 trials with random seed 0. Collinear samples and singular homographies are skipped. A match is an inlier when the Euclidean distance between its projected image-1 point and its actual image-2 point is less than 3 pixels. I keep the largest inlier set, breaking ties by total inlier error, then refit using all inliers with up to three rounds of reclassification.

predicted_point_2 = H * [x_1, y_1, 1] (divide by its third coordinate) error = sqrt((predicted_x_2 - x_2)^2 + (predicted_y_2 - y_2)^2) inlier = error < 3 pixels

For automatic stitching, the homography is estimated entirely from detected and matched features. The manual correspondences are used only for the Part A comparison. Both methods keep image 1 fixed, inverse-warp image 2 using bilinear interpolation, and use the same feather blending. Black areas are outside the source images.
